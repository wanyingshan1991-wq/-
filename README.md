# 业绩表格生成工具

这是一个给团队内部使用的飞书业绩表格自动生成项目。建议把这个 GitHub 项目交给 WorkBuddy、Codex 或其他 Agent 软件处理，让 Agent 帮你下载、检查环境、运行入口和按提示生成表格。

当前支持：

- 生成 `经营方针修正-X月`
- 生成 `事业年月计划-X月`
- 生成 `事业资源分配计划-X月`
- 生成 `营销资源分配计划-X月`
- 生成 `研发资源分配计划-X月`

## 给 Agent 的一句话

把 GitHub 链接发给 Agent 后，可以直接说：

```text
请打开这个 GitHub 项目，下载或 clone 到本地，检查 Python 和 lark-cli，完成飞书授权，然后运行 first_time_setup.bat。之后请运行桌面的“业绩表格生成工具”，按我要生成的表格提示，让我粘贴对应飞书链接并确认执行。
```

如果已经配置过这个 GitHub 项目的朋友，通常不需要重新配置。工具会继续读取本机已有的：

```text
config/config.json
```

新增表格的链接会在第一次生成该表时再询问，并自动保存到本机配置里。

## 首次设置

首次设置只做环境和入口准备，不要求一次性输入所有表格链接。

Agent 应执行：

```text
first_time_setup.bat
```

它会做：

1. 检查 Python
2. 检查 `lark-cli`
3. 创建本地配置文件
4. 创建桌面入口

如果系统安全策略禁止创建 `.lnk` 快捷方式，工具会自动改为创建桌面 bat 入口：

```text
业绩表格生成工具.bat
```

## 日常生成

双击桌面入口：

```text
业绩表格生成工具
```

主菜单：

```text
1. 生成经营方针修正-X月
2. 生成事业年月计划-X月
3. 生成事业资源分配计划-X月
4. 生成营销资源分配计划-X月
5. 生成研发资源分配计划-X月
8. 按需重新配置链接
9. 检查环境和飞书授权
0. 退出
```

## 生成事业年月计划

选择：

```text
2. 生成事业年月计划-X月
```

第一次生成时，工具会要求粘贴：

```text
事业年月计划表格链接
```

之后会自动保存。下一次生成同一类表时，不需要再次输入。

生成 `X月` 时，脚本会：

1. 在同一个表格内从 `X-1月` sheet 复制出 `X月` sheet
2. 将 Row `6/9/13` 的 `1月` 到 `X月` 实绩调整区域设为白色
3. 更新 `R/S/T` 列完成率公式
4. 清空 `E14` 原因分析和 `E15` 基本对策，保留给人工填写

事业年月计划必须先于事业资源分配计划生成，因为后续事业资源分配计划要引用事业年月计划中的 `E15:U15` 基本对策。

## 生成资源分配计划

现在支持三张资源分配表：

```text
3. 生成事业资源分配计划-X月
4. 生成营销资源分配计划-X月
5. 生成研发资源分配计划-X月
```

第一次生成某一张表时，工具会要求粘贴对应飞书表格链接。之后会自动保存，同一台电脑不用重复输入。

生成 `事业资源分配计划-X月` 时，脚本会：

1. 从 `X-1月` sheet 复制出 `X月` sheet
2. 更新 `C12` 为 `X月`
3. 在 `C3` 写入事业年月计划 `X月!E15:U15` 的引用公式
4. 在 `C4:C10` 写入固定方针标题
5. 在 `D4:D10` 写入方针修正 `(X-1)月` 中 `X月` 列的引用公式
6. 清空 `C13:C14`，保留给人工填写研发和营销核心工作要求

生成 `营销资源分配计划-X月` 时，脚本会：

1. 从 `X-1月` sheet 复制出 `X月` sheet
2. 更新 `C8` 为 `X月`
3. 在 `C3` 引用事业资源分配计划 `X月!C14`
4. 在 `C4:C6` 写入固定方针标题
5. 在 `D4:D6` 写入营销相关方针引用公式
6. 清空 `C9`，保留给营销部门人工填写核心工作计划

生成 `研发资源分配计划-X月` 时，脚本会：

1. 从 `X-1月` sheet 复制出 `X月` sheet
2. 更新 `C9` 为 `X月`
3. 在 `C3` 引用事业资源分配计划 `X月!C13`
4. 在 `C4:C7` 写入固定方针标题
5. 在 `D4:D7` 写入研发相关方针引用公式
6. 清空 `C10`，保留给研发部门人工填写核心工作计划

方针引用会优先从已配置的方针修正文件夹里查找：

```text
经营方针修正-(X-1)月
```

找不到时，才使用本机配置里保存的方针修正源表 token。

## 生成经营方针修正

选择：

```text
1. 生成经营方针修正-X月
```

生成 `X月` 时，工具会优先在同一个文件夹里查找并复制：

```text
经营方针修正-(X-1)月
```

如果找不到上一月表，才会使用本机配置里保存的源表作为兜底模板。

脚本会把 `1月` 到 `X月` 的“经营方针调整”区域设为白色背景。

## 推荐生成顺序

准备 `X月` 月会材料时，推荐顺序是：

```text
1. 确认 经营方针修正-(X-1)月 已完成
2. 生成 事业年月计划-X月
3. 生成 事业资源分配计划-X月
4. 生成 营销资源分配计划-X月
5. 生成 研发资源分配计划-X月
```

当前仓库已经实现上述 5 项。后续会继续加入销售/研发月周推移计划和个人计划。

## 环境和授权

本工具通过本机 `lark-cli` 操作飞书表格。飞书机器人配置不等于本机已经有 `lark-cli`。

Agent 可用以下命令检查：

```bash
lark-cli --version
lark-cli auth status --json --verify
```

需要授权时：

```bash
lark-cli auth login --domain docs --domain drive
```

## 安全说明

- 不要提交 `config/config.json`
- 不要把 access token、refresh token、app secret 放进 GitHub
- `config/config.example.json` 是空模板
- 每个使用者的真实飞书链接只保存在自己的电脑里

## 当前限制

- 当前只支持飞书
- 当前通过 `lark-cli` 操作飞书，不是独立飞书机器人
- 新电脑需要先安装并授权 `lark-cli`
- 销售/研发月周推移计划和个人计划还未加入脚本生成
